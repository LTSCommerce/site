PHP 7 - The Future is Now.. Get On Board

Created on 2017-03-02 10:32

Published on 2017-03-02 12:05

PHP 7 was released on the 3rd of December, 2015. That's well over a year ago now. It brought some major improvements which benefit everyone from developers who get to use stricter type hinting through to website owners who simply get a huge performance boost practically for free.

Since then PHP 7.1 has also been released on the 1st of December 2016. If you are still running PHP 5 then you are definitely falling behind the times!

So why isn't everyone who is running a PHP site already using PHP 7?

Well there are quite a few answers to this, though I suspect it is mostly just inertia.

Problem 1 - Bugs and Compatibility

Developers might be afraid that upgrading to PHP 7 could bring a huge influx of bugs and difficult to fix language incompatibilities.

Solution

Most open source software now supports PHP 7 natively. If not then there is generally a community driven solution to document and patch any PHP 7 issues. The first step would be to upgrade to the latest version of your particular platform.

For bespoke code bases, or those where the platform does not support it and you will need to fix it yourself, then the job can be sped up hugely by running static analyses tools which will tell you exactly which bits of your code are not PHP 7 compatible so you can go and fix them. At the least this gives you clear visibility on what you actually need to do.

Problem 2 - Not Available on Server or Hosting

Your server might not currently give you an option to install PHP 7 or your hosting company might not be able to offer it to you.

Solution

If you manage your own server then you should be able to find a way to install PHP 7. If you can't then contacting an expert web development agency would be a good start.

If you have managed hosting or do not have a dedicated/virtualised server then you need to talk to your hosting company and ask them to do the upgrade for you.

If your hosting company is not able to offer you PHP 7, then you just have to move. There are plenty of hosts who specialise in PHP and would gladly help you get up and running with PHP 7.

How to Proceed with an Upgrade

Never make this kind of change directly on a live server. You need to test everything first to make sure it is all going to work. You also need to have a clear fall back plan in case things do not work out.

Setting up a test environment that is running PHP 7 should not be a challenge for you or your development agency. You can then make sure that everything is working properly before you plan your upgrade.

When you are ready to upgrade, you have the choice of upgrading the server you are running on or - a better option - provisioning a new server with the latest operating system and of course PHP 7 already installed. This way you have a built in fail over plan to simply revert to using your existing server.

Whichever way you do it, it's worth making sure that its being handled properly and that the risks have been made as low as possible. There should be no need for any appreciable down time.
